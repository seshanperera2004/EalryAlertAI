# EarlyAlertAI

Predictive analytics & behavioral intelligence system for early detection of student burnout
and academic risk — built by the **AI and Data Science Club, General Sir John Kotelawala
Defence University (KDU)**.

> **Status:** proof-of-concept pipeline running on a **synthetic dummy dataset**, built while
> the club awaits administrative approval to access real, anonymized KDU LMS / attendance / CA
> data. The dummy data is shaped exactly like the real data we expect, so switching to the real
> dataset later is a data-loading change, not a rebuild.

## What's in this repo

```
EarlyAlertAI/
├── data/
│   ├── generate_dummy_data.py     # synthetic dataset generator (stdlib `random` only)
│   └── students_dummy.csv         # generated output (600 synthetic students)
├── model/
│   └── train_model.py             # trains the ensemble model, evaluates it, scores students
├── dashboard/
│   ├── index.html                 # advisor-facing risk dashboard
│   ├── style.css
│   ├── script.js
│   ├── risk_scores.json           # generated by train_model.py
│   └── model_metrics.json         # generated by train_model.py
└── requirements.txt
```

## How the pieces fit together

1. **`data/generate_dummy_data.py`** creates 600 synthetic student records with four
   engineered behavioral features named in the project proposal:
   - `attendance_decline_pct`
   - `lms_inactivity_gap_days`
   - `assignment_delay_index`
   - `grade_volatility_score`

   Risk tiers are correlated but noisy, and a small slice of "hidden risk" students (good
   grades, rising disengagement) is included on purpose — that's exactly the pattern
   EarlyAlertAI exists to catch early.

2. **`model/train_model.py`** trains a soft-voting ensemble of **Random Forest, XGBoost, and
   Logistic Regression**, evaluates it (accuracy, precision, recall, F1, ROC-AUC, 5-fold CV),
   then scores every student and explains each score with **SHAP** (top 3 contributing
   factors per student). Results are written to `dashboard/risk_scores.json` and
   `dashboard/model_metrics.json`.

3. **`dashboard/`** is a static HTML/CSS/JS site — no build step, no backend — that reads
   those two JSON files and renders:
   - Summary counts (Low / Moderate / High risk)
   - A filterable, searchable student roster sorted by risk score
   - A detail panel per student showing the SHAP-based "why this score" breakdown

## Running it locally

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Generate the synthetic dataset
python3 data/generate_dummy_data.py

# 3. Train the model and generate risk scores for the dashboard
python3 model/train_model.py

# 4. Serve the dashboard (fetch() needs http://, not file://)
cd dashboard
python3 -m http.server 8000
# then open http://localhost:8000
```

## Moving from dummy data to real data

Once KDU's administrative and ethical approvals are in place:

1. Replace `data/students_dummy.csv` with a real, anonymized extract matching the same
   columns (or adapt the loader in `model/train_model.py`).
2. Re-run `python3 model/train_model.py` — it regenerates both JSON files the dashboard reads.
3. Everything else (dashboard UI, filtering, SHAP explanation panel) works unchanged.

## Ethical & governance notes (per the project proposal)

- All data used here is synthetic; no real student data is included in this repository.
- In production, all student data will be anonymized before processing, with bias monitoring
  across gender and faculty groups.
- The system is a **decision-support tool only** — every flagged case is reviewed by an
  academic advisor or student welfare officer before any action is taken.
